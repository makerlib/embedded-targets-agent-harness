## Decisions

- **Retry rules** apply to *baseline* and *verification* attempts per rework
  cycle. Development checks and test-design runs repeat freely and never count
  toward the verification level. Gate retries are always explicit (with a
  reason); the executor's automatic retry policy exists for generic steps.
- **Attempt numbers** are shared across purposes for a gate.
- **Timeouts** give INCONCLUSIVE (`GATE_TIMEOUT`). A missing executable gives
  BLOCKED (`MANDATORY_DEPENDENCY_UNAVAILABLE`). A failed precondition or
  dependency gives BLOCKED (`GATE_PRECONDITION_FAILED`). None of these is
  skipped.
- **Baseline** runs all required gates. `must_pass` gates must pass;
  `record` gates (acceptance tests) may fail but must run.
- **Repository diff.** `evidence/git_diff.py` calls git directly (with a
  throwaway index) because `GitPort` has no patch method; it should move
  behind the port.

## Known limitations

- **Read-only files don't stop root.** File modes do not stop a root process
  (this container runs as root); immutability of attempts rests on write-once
  creation plus hash verification by `evidence validate`.
- **Unreaped grandchildren.** On timeout the process group is killed;
  grandchildren in this container become zombies because its init does not
  reap them (verified in the test).
- **Unknown preconditions are rejected.** Package preconditions such as
  `matlab_available` arrive with the MATLAB port (HK-006).
- **No authoritative evidence yet.** Authority is always advisory until
  HK-013.
