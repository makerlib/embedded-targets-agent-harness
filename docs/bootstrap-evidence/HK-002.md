## Findings

1. **YAML 1.1 booleans (fixed).** PyYAML loads `off`, `on`, `yes` and `no` as
   booleans, so the spec's own example `qe_test_design: off` failed
   validation. The kernel loader now uses YAML 1.2 booleans (`true`/`false`
   only); the global `yaml.safe_load` is not patched. Projects whose
   configuration relied on `yes`/`no` as booleans must write `true`/`false`.
2. **Approval content hash (fixed before commit).** An early version hashed
   the unapproved and approved shapes differently, so every approval read as
   "changed after approval". Tests caught it; `strip_approval` now produces
   one canonical pre-approval form.
3. **Lite model rule (decision).** "No model path in the allowed scope" is
   checked two ways: a glob that explicitly targets model files, and, when
   the kernel supplies the tracked file list (HK-003 at `INITIALISING`), any
   existing model file under an allowed glob. Treating every `**` glob as
   "could contain a model" would make almost no contract lite-eligible.

## Known limitations

- Local approvals are unauthenticated (§9.13). The agent-identity check is a
  `DETECTED`-tier control: it refuses known agent IDs and requests from
  kernel-launched sessions (`ET_HARNESS_AGENT_INSTANCE`, set from HK-007), but
  a person can type any name.
- Gate levels for package gates come from `project.yaml` `gate_levels` until
  the gate registry (HK-004).
- Templates are read from the source tree (or `$ET_HARNESS_TEMPLATE_DIR`), like
  schemas.
