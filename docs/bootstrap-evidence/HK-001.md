## Decisions and assumptions

- State files are stored as canonical-hash-verified JSON, not YAML, to avoid
  YAML type ambiguity in hashed records.
- The state store appends the audit entry first, then replaces the state file.
  A crash between the two leaves the prior state intact. On the next load this
  is recognised as `STATE_WRITE_INTERRUPTED` (audited as
  `state.write_rolled_back`), not as tampering.
- Built-in defaults are not a precedence layer. They fill keys no layer sets
  and never tighten a layer's choice.
- Added reason codes as kernel extensions (§27 says "at least"):
  `CONFIG_WEAKENING_REJECTED`, `REPOSITORY_NOT_FOUND`,
  `REPOSITORY_COMMAND_FAILED`, `STATE_NOT_FOUND`, `STATE_WRITE_INTERRUPTED`,
  `INTERNAL_ERROR`.
- The Git adapter lives in `src/et_harness/repository/adapters/` so it is
  importable. The top-level `adapters/git/` path allowed by the contract is
  unused.
- `canonical_json_bytes` implements RFC 8785 for strings, integers, booleans,
  null, arrays and objects (UTF-16 key ordering) and rejects floats. Full
  number handling for feature contracts is HK-002.

## Known limitations

- Schemas are not bundled in a wheel; they resolve from the source tree or
  `$ET_HARNESS_SCHEMA_DIR`.
- The audit log has no inter-process lock (single writer assumed).
- `changed_paths` on the Git CLI adapter writes blob objects for untracked
  files into the object database (via a temporary index). The real index and
  working tree are untouched.
- Rename and copy detection is exact-content only.
