## Decisions and findings

- **No §27 code for "mandatory gate failed".** Adding one would change the
  generated audit-record schema (protected here). A failed gate's finding
  carries the attempt's own codes, if any, and the verdict lists
  `failed_gates`. **Spec finding for 1.1.2:** add `GATE_FAILED`.
- **Verdict files.** `verdict.yaml` is written only for final verdicts
  (PASSED, FAILED). BLOCKED, INCONCLUSIVE and rework evaluations are kept as
  write-once `evaluations/evaluation-NNN.yaml`, because those states can
  resume and be evaluated again.
- **Approval rules are in place, but no approval records exist yet.** Until
  HK-011 there are no approval records, so `human_review` criteria, changed
  models, L5/L6 and Class D/E always BLOCK.
- **Scope is evaluated in WORK mode** until a candidate commit exists
  (HK-008), then in CANDIDATE mode, where committed derived artefacts fail.
- **Consequence:** real workflows evaluate to INCONCLUSIVE until HK-008 to
  HK-012 (and HK-010 for the open initialisation check) exist.
