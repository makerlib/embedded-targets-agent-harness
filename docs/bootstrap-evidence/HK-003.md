## Decisions

- **Unavailable initialisation checks are recorded, not claimed.** Package
  resolution (HK-009), baseline gates (HK-004) and host guards with
  enforcement probes (HK-010) appear as `not_implemented` checks in the state
  file and `workflow status`. The workflow still reaches PLANNING so later
  features can be built. The evaluator (HK-005) must treat open checks as
  preventing PASSED.
- **The tamper rule on a BLOCKED workflow** replaces the blocker (revision +1,
  `blocker.raised`) instead of a BLOCKED to BLOCKED transition, which §9.19.3
  does not list.
- **`workflow cancel` follows §15 literally:** only BLOCKED can be abandoned,
  so an active workflow is first blocked with a reason code.
- **The workflow ID is the state store's audit key**, read from the
  last-known-good copy first, so editing the ID in the state file cannot hide
  it from verification.
- **The transition event is appended after the state write.** A crash between
  the two leaves a valid state whose history records the transition but whose
  audit log lacks the `state.transition` event.

## Findings

- `contracts/` and `artefacts/` (from HK-002) have no `__init__.py`. An
  isolated wheel build shows setuptools includes them as namespace packages,
  so this is not a packaging defect. Add the files in HK-004, whose scope can
  include those paths. `orchestration/` got one here.
- `pip wheel --no-build-isolation` fails with the system setuptools
  (`install_layout`); the default isolated build works. This is an
  environment quirk.
